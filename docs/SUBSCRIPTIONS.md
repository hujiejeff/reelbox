# 配置订阅

一条地址(`index.json`)装齐**源 + 源插件 + 适配器**。**同一时刻只有一份生效**,切换 = 整体换一套源。

```
用户这一头                              仓库那一头
┌─────────────────────────┐          ┌──────────────────────────┐
│ subscriptions.json      │          │ index.json  v1.0.0       │
│  active: "s264642d9"    │  拉取     │  ├ sources[]   ← 源       │
│  items: [local, s264…,  │ ◀────────│  ├ plugins[]   ← 源插件    │
│          f1a2…]         │          │  └ adapters[]  ← 适配器    │
│ subs/<id>.json  ← 快照   │          │ plugins/*.js             │
│ sources.json    ← 生效的 │          └──────────────────────────┘
└─────────────────────────┘
```

代码:解析与挑错在 `core/src/sub.rs`(纯逻辑,有单测),IO 在 `src-tauri/src/sub.rs`。

## 为什么是"切换"而不是"叠加"

源是"同一件事的不同来源":同一个片子在几个站都有,叠加进来只会让搜索出来一堆重复。切换模型下,"
我现在用哪套"永远只有一个答案,`sources.json` 就是那套的投影。

代价是:改了源之后要决定这套改动归谁。做法是**不在编辑时打断你**,而是在两个地方露出来:

- 生效那一行上出现「有本地改动」徽标,行尾「更多」里多一个「存成新订阅」
- 点「更新」时才拦一下(那一刻才会真的覆盖),三选一:取消 / 直接更新 / 存成新订阅

编辑本身什么都不会丢 —— 只有"更新这份订阅"和"切换走"才会动 `sources.json`。

## 页面长什么样

和「源」「适配器」两页同一套交互:页头右上角「添加」(地址 / 本机路径 / 选择文件都行),
中间是一行行订阅(当前生效那行容器是主色、名字加粗),行尾「更多」里放检查、更新、导出、删除;
页脚两个整页动作:「全部检查更新」和「重置」。

## 切换时会问一句

切换是**完整替换**:`sources.json` 整个换成目标那份。所以点「切换」先弹一个框:

| 选项 | 做的事 |
| --- | --- |
| **备份并切换**(默认) | 先把当前这套导出成 `exports/<名字>-<时间>.json`,再切换 |
| 直接切换 | 只切换(当前这套仍存在它自己的快照里,切回来还在) |
| 取消 | 什么都不做 |

备份文件和导出的格式一样,是一份合法的 `index.json`,以后用「从文件…」就能导回来。

当前配置是空的(0 条源)时不问,直接切。

## 每份订阅都有本地快照

`subs/<id>.json` 存着这份订阅上次应用的内容。所以:

- 切走再切回**不用联网**
- 断网也能切
- 远程订阅挂了不影响已经装好的这份

`sources.json` 始终等于"当前生效那份的快照",两者不一致就是 `dirty`(有未保存的本地改动)。

## 三种来源

| 类型 | 身份 | 怎么更新 |
| --- | --- | --- |
| **本地配置**(`local`) | 内置,删不掉 | 直接改源即可 |
| **远程订阅**(`remote`) | 索引地址的指纹 | 拉 `index.json` |
| **本地文件订阅** | 一个 json 文件的路径 | 重新读那个文件 |
| **从文件导入** | 内容直接存成快照 | 不会自动更新(没有来源了) |

后两种都是"本地订阅",区别只在有没有 `path`:有 path 的每次同步重读那个文件(适合放 git 里自己维护),
没有 path 的就是一份自包含的快照。

## index.json

```jsonc
{
  "schema": "reelbox-index/1",
  "name": "reelbox 基础配置",
  "version": "1.0.1",            // semver,只增不减;应用靠它判断有没有更新
  "updated": "2026-11-22T08:00:00Z",
  "homepage": "https://github.com/hujiejeff/reelbox-config",

  "adapters": [ { "id": "hgpub", "name": "HGhub 适配器",
                  "path": "hgpub.adapter.js",     // 只写文件名
                  "version": "2.0.0", "sha256": "…", "minApp": "0.2.3" } ],
  "plugins":  [ { "id": "4k", "path": "4k.reelbox.js", "sha256": "…" } ],

  "sources":  [ { "id": "ffzy", "name": "非凡资源", "type": "vod",
                  "url": "https://…/provide/vod", "adapter": "vod" } ]
}
```

**版本号用 semver**:`1.0.0`。加/删/改一条源 → 升最后一段(`1.0.1`);换了结构 → 升中间那段。
应用只比版本号,不看 `updated` —— 时间戳会骗人,版本号不会。

`path` 有两种写法:

- **文件名**(常规):应用只扫 `plugins/` 第一层,子目录等于没装。真实地址是
  `<index 所在目录>/plugins/<path>`,由 `core::sub::code_url` 拼 ——
  同一份索引放 raw / jsDelivr / Pages 都能用
- **完整的 http(s) 地址**:文件放在别的仓库或 CDN 时用。此时这份索引就绑在那个域名上了,
  换入口得改索引;落盘时取 URL 最后一段当文件名

不管哪种,装的时候都是**下载到本机** `plugins/<文件名>`,运行时读本地文件,不再联网。

源上的字段和 `sources.json` 一样(见 [SOURCES.md](SOURCES.md)):
`verify` / `verifyUrl`(人工校验)、`posterRatio`(封面比例)、`options`(引擎插件配置)。

## 安装前先体检

`core::sub::problems` 一次列出所有毛病,有一条不合格就整份不装 —— 半装状态比不装更难收拾。

| 检查 | 为什么 |
| --- | --- |
| `schema` / `version`(semver)/ `updated` | 这是不是一份索引、版本写没写规范 |
| id 全局唯一 | 源、插件、适配器共用一个命名空间,重名之后认不出谁是谁 |
| 适配器名不是内置的 | `vod`/`iplayr`/`m3u`/`reelbox` 靠 `@builtin-version` 升级,订阅不能抢这个位置 |
| 源的 `url` 是 http(s) | 本地路径的源别人装了是坏的 |
| `adapter` 有出处 | 内置的,或本索引 `adapters` 里声明的 |
| `sha256` 64 位十六进制 | 少了它就没法判断文件被改过没有 |
| `minApp` | 新适配器用了旧应用没有的能力时,装之前就拒绝 |

## 文件的三方比对

对每个 `plugins/` 下的文件,拿**三方**比:索引里的 sha256、磁盘上现在的、上次装的时候记下的。

| 情况 | 动作 |
| --- | --- |
| 磁盘上就是索引要的那份 | 什么都不做 |
| 磁盘上 ≠ 上次记的 | 用户改过 → 不覆盖,写进报告的 `skipped` |
| 磁盘上 = 上次记的 | 用户没动过 → 覆盖 |
| 文件不存在 | 下载,校验 sha256,写盘 |

## 检查更新

`sub_check(id)` 只拉索引读版本号,不改任何东西;`sub_check_all()` 把所有订阅跑一遍。
行上出现「可更新 1.0.1」徽标时,点「更多 → 更新到 1.0.1」才会真的应用。

版本比较在 `core::sub::ver_cmp`(按段比数字,`1.0` 和 `1.0.0` 相等)。

## 导出 / 复制 / 重置

- **导出**:把某份订阅的内容写成 `exports/<名字>-<时间>.json`(就是一份合法的 `index.json`,可以直接给别人)
- **复制**:把当前这套源另存成一份新的本地订阅并切过去 —— 就是"改订阅"的正规做法
- **重置**:清空所有订阅和源,回到空白本地配置。原来的 `sources.json` 先备份成 `sources.bak-<时间>.json`

## 网络与可达性

拉取走和插件同一套网络层(系统代理 → 直连,按域名记 30 分钟):

- `raw.githubusercontent.com` 在国内经常连不上 → 换 jsDelivr:
  `https://cdn.jsdelivr.net/gh/<user>/<repo>@<tag>/index.json`
- **环回地址永远直连**:`localhost` / `127.x` 不走系统代理(代理多半在别的机器上)

## 私有仓库

`raw.githubusercontent.com` 对私有仓库不生效(带 token 也拿不到)。要用私有仓库得走
`api.github.com/repos/{owner}/{repo}/contents/{path}` + fine-grained PAT。当前版本只支持公开仓库 ——
私有订阅要先决定 token 存在哪,还没做。

## 已知边界

- 两条订阅带**同名文件**时,后装的覆盖先装的;前一条下次同步会当成"用户改过"跳过(报告里能看到)
- 没有 ETag 缓存:每次检查都完整拉一次索引(几 KB,可以接受)
- 不校验索引来源的可信度:装第三方订阅 = 运行别人的 JS(沙箱挡 DOM/IPC/文件,挡不住发网络请求)

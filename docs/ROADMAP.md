# 迭代路线

单机自用 + 兼顾移动端。每条标了工作量:小 ≤0.5 天 / 中 1–3 天 / 大 ≥1 周。

## 贯穿性主题

两件事不属于某个版本,但每个版本都要往里填:

- **源解析支持**:能吃的源格式越多,这个 App 越有用。见下文「源解析 backlog」。
- **移动端**:每个版本都要过一遍 600px 以下的形态,不做事后补救。

## 源解析 backlog(贯穿性)

按「价值 / 成本」排序。每支持一种,可用源数量就多一批。

### 已支持

| 格式 | 说明 |
| --- | --- |
| 苹果 CMS v10 JSON | `?ac=list` / `?ac=detail&ids=` |
| 苹果 CMS v10 XML | `.../at/xml` |
| WeBox 插件 | `.webox.js`,sandbox iframe 内执行,支持 wasm |
| 分享页抽流 | dytt 类,从 HTML 里抽 m3u8(含相对路径) |

### 待支持

| 格式 | 现状 | 计划 | 量 |
| --- | --- | --- | --- |
| **iplayr 爬取配置** | 导入时被识别并跳过 | 写一个通用 HTML 爬取驱动:按 JSON 里的 `category.url0/url1`、`referer`、`user_agent` 抓列表,再按详情页规则抽取。需要先逆向出其字段约定 | 大 |
| **TVBox 接口** | 不支持 | TVBox 的 `{sites:[{key,name,type,api}]}` 里 `type=0/1` 多为 CMS,可直接映射;`type=3` 是 jar/spider,暂不碰 | 中 |
| **m3u8 直播源** | 播放链路已通(适配器 + 直播模式) | v0.3 | 中 |
| **m3u 本地/远程列表** | 计划中 | 与上同,同一解析器 | 小 |
| **CMS 变体** | 部分站点的 `class`/`ty` 结构不同、分页参数不同 | 加兼容开关:分页参数名、是否要 `ac=detail` 取列表、`$$$` 分隔符变体 | 中 |
| **需要 Referer/UA 的接口** | 目前固定 UA,无 per-source 头 | 源模型加 `headers`,v0.4 与「按源覆盖」一起做 | 小 |
| **需要登录/签名的接口** | 不支持 | 暂不做(涉及凭据存储) | — |
| **WebDAV / 网盘 / 本地文件** | 不支持 | 暂不做 | — |

### 调优项

- CMS 列表默认走 `ac=detail`(拿封面),部分源在 detail 下慢得多 → 可配置成 `ac=list`
- 分类接口失败时退回「全部」,不要整页报错
- 源站 TLS 握手慢(记录过 30s)→ 可配置超时与重试次数
- 插件源首调慢(沙箱冷启动)→ 预热与结果缓存
